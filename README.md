# Reproducibility deposit: the accelerated 5x+1 predecessor-count exponent

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.22182794.svg)](https://doi.org/10.5281/zenodo.22182794)

Code, data and outputs behind every number in the paper *A calibrated
computational study of the accelerated 5x+1 predecessor-count exponent*
(Renato Augusto Tavares, Universidade Federal de Goias).

The paper asks whether the counting exponent of the true arithmetic reverse
tree of the accelerated 5x+1 map separates the Kontorovich-Lagarias predicted
value, 0.650919, from a competing stochastic model due to Volkov, 0.678. The
two authors flagged the question as open in 2009 for want of discriminating
data. The obstacle is that a raw fixed-window reading sits 0.038 below the
assigned target of a control tuned to a known one,
larger than the 0.027 that separates the two predictions, so the reading is
calibrated against synthetic constructions that share the arithmetic tree's
admissible-exponent structure and preserve either its exact affine sibling
recurrence or the multiplicative relaxation of it, according to the control
family, in matched pairs that either preserve or remove the residue
congruence, and are assigned a chosen annealed pressure target.

The headline measurement, at checkpoint decade 1e9 to 1e10: the arithmetic
tree reads 0.64926. That is inside the span of the four constructions built to
0.650919, and 0.02432 below the lower of the two built to 0.678, with 95%
bootstrap interval [0.0208, 0.0273] on that difference. The interval takes the
smaller of the two 0.678 readings inside each resample, so it carries the cost
of the conservative choice.

Six constructions, not four: the two built to 0.678 and the fourth built to
0.650919 differ from their partners in a single rule, whether each child draws
its own residue or advances cyclically from one drawn at the parent. That
second construction at 0.678 was added in response to an external referee, who
observed that a spread measured on one target was being carried to another
target where it had never been checked.

## What is here

| Folder | What it does |
|---|---|
| `experiments/E-001-qx1-empirical-gate/` | the fixed-window estimator, the pressure equation, and the truncation extrapolation |
| `experiments/E-002-kl-volkov-window-calibration/` | the C enumerator and the calibrated comparison; this is where the headline number comes from |
| `experiments/E-003-multitype-perron-root/` | the multitype Perron root and its type-closure check |
| `experiments/E-004-volkov-cutoff-bias/` | a reimplementation of Volkov's stopping rule, to see what his threshold costs |

Each folder has its own `README.md` with the full account, an evidence block
naming the exact commands that produced every committed output, and a
`Parallelism:` field stating why each computation is parallel or serial.

## Reproducing

Requirements: a C compiler with OpenMP, and Python 3.12 with `numpy` and
`scipy`. Everything was run on Linux 7.0.0-30-generic, Intel Core 7 240H
(16 threads), 62 GiB RAM, with Python 3.12.3, numpy 2.5.1 and scipy 1.18.0.

Build the enumerator first, since several analysis scripts drive it:

```sh
cd experiments/E-002-kl-volkov-window-calibration
gcc -O3 -march=native -fopenmp -o tree_counts tree_counts.c -lm
python3 validate_vs_python.py     # must print VALIDATION PASSED
```

Then run any experiment's declared commands, which are listed verbatim in its
own `README.md` under `Command:`. The quick path to the headline number:

```sh
python3 summary.py b15 10         # all seven readings at 1e9 -> 1e10
python3 referee_tables.py         # the paper's two tables
python3 paired_bootstrap.py       # the conservative separation and its interval
python3 decade_sweep.py           # the same comparison at every checkpoint decade
```

## What reproduces, and what does not

Every committed log under any `out/` directory reproduces byte for byte from
the committed code and data, with two exceptions in `E-001`:
`experiment_gate_richardson.log` and `validate_singlepass_vs_perbuffer.log`
each carry an embedded wall-clock figure that changes between runs. Every
number in them reproduces. To compare them, use the filter that ships beside
them, which neutralises the clock and leaves the rest of the line intact:

```sh
cd experiments/E-001-qx1-empirical-gate
./diff_ignoring_clock.sh new.log out/experiment_gate_richardson.log
./diff_ignoring_clock.sh --selftest      # its own negative controls
```

Two committed count files are large runs rather than instants:
`data/q5_arith_b17.txt` is a deep run of about 824 s, and `run_deep.sh` takes
tens of minutes. The `data/mc_*.txt` files are **not** committed; they are
regenerated by `check_mean_vs_annealed.py` on its first run.

## Negative controls

Three checks in this deposit ship with executed negative controls, because a
check that has never been shown to fail is not evidence of anything:

```sh
python3 annealed_brute.py --selftest      # one probe per link of the chain
python3 cycle_membership.py --verify-c    # the splitmix64 replica against the C
./diff_ignoring_clock.sh --selftest       # three mutations the filter must catch
```

`cycle_membership.py` also checks, on every ordinary run, that its two root
samplers still agree with their sources, and audits its own step cutoff by
re-running at twice the cutoff and requiring the same count.

## A note on the two root samples

This project has **two** samples of 300 roots and they are not the same set;
they share 31 roots. The E-001 sample comes from Python's
`random.Random(2026)` and backs sections 4 and 5 of the paper. The E-002
sample comes from the C enumerator's own splitmix64 and backs section 6 and
every `data/q5_*` count file. Confusing them produces numbers that are correct
for the wrong object, which happened once during review and was caught.
`cycle_membership.py` reports both, labelled.
